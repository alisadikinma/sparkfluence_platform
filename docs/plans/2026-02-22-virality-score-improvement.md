# Virality Score Improvement — Scoring Engine Recalibration + LLM Prompt Enhancement

**Date:** 2026-02-22
**Status:** Design
**Goal:** Consistently produce virality scores 85-95% (currently landing at 40-60%)

---

## Problem Statement

Scripts generated by the LLM are scoring 40-60% virality despite:
1. `scoringOptimizer.ts` already injecting all scoring rules into the LLM prompt
2. A "SCORING CHEAT SHEET" in the user prompt requiring specific features per segment
3. A 39-point Self-Verification Checklist

**Root causes (dual):**
- Scoring engine feature detection is too strict (narrow regex, harsh continuous scoring)
- LLM doesn't consistently produce all required scoring features despite instructions

---

## Part 1: Scoring Engine Recalibration

### 1.1 Continuous Feature Scoring (scriptAnalysis.ts → `extractFeatures`)

**Problem:** Many features return 0.2-0.3 for "normal" content, causing massive point loss.

#### `has_specific_detail` (BODY weight: 12, FORE weight: 10)
```
BEFORE:                          AFTER:
hasNumber → 1.0                  hasNumber → 1.0
has proper noun → 0.7            has proper noun → 0.8
else → 0.3                       has concrete noun → 0.6
                                  else → 0.45
```
**Add concrete noun detection:** common nouns that indicate specific content (brand-like words, tool names, place names, technique names).

#### `has_value_delivery` (BODY weight: 13)
```
BEFORE:                          AFTER:
has action verb → 1.0            has action verb → 1.0
hasNumber → 0.6                  has explanatory pattern → 0.8
else → 0.2                       hasNumber → 0.7
                                  else → 0.4
```
**Add explanatory pattern:** sentences that teach/explain ("karena", "jadi", "artinya", "yang bikin", "because", "so that", "which means").

#### `emotional_intensity_high` (PEAK weight: 12)
```
BEFORE:                          AFTER:
intensity >= 0.6 → 1.0           intensity >= 0.5 → 1.0
intensity >= 0.4 → 0.6           intensity >= 0.35 → 0.7
else → 0.2                       intensity >= 0.25 → 0.5
                                  else → 0.3
```
**Also:** Count power words as intensity boost (+0.15 per power word found).

#### `has_emotional_climax` (PEAK weight: 18)
Currently requires emotion intensity > average of all segments + 0.1 for score 1.0. This is too strict when all segments have similar intensity.

```
BEFORE:                          AFTER:
> avg + 0.1 → 1.0                > avg + 0.05 → 1.0
> avg OR climax indicator → 0.7  > avg OR climax indicator → 0.8
climax indicator only → 0.5      climax indicator only → 0.6
else → 0.3                       else → 0.35
```

### 1.2 Cross-Segment Feature Defaults (scriptAnalysis.ts → `extractFeatures`)

**Problem:** 6 cross-segment features default to 0.4-0.5 when detection is imprecise.

#### `builds_on_hook` (FORE weight: 12)
```
BEFORE: overlap / min(hookWords.size, 3) — requires 3+ keyword matches
AFTER:  overlap / min(hookWords.size, 2) — requires 2+ keyword matches
        Also add thematic overlap: if both texts share same topic category → 0.7 minimum
```

#### `matches_hook_category` (HOOK weight: 5)
```
BEFORE: default 0.4 when no specific pattern match
AFTER:  default 0.6 — most hooks naturally align with their content
```

#### `matches_funnel_stage` (CTA weight: 7)
```
BEFORE: hasCtaAction || hasValueDelivery > 0.5 ? 0.8 : 0.4
AFTER:  hasCtaAction ? 1.0 : hasValueDelivery > 0.5 ? 0.8 : 0.5
```

### 1.3 Pattern Detection Expansion (scriptAnalysis.ts → `extractFeatures`)

#### `has_pattern_interrupt` — Expand Indonesian patterns
```
BEFORE regex covers:
  ALL CAPS 2+ chars, hasForeshadow(), specific phrases

ADD these Indonesian conversational interrupts:
  /\b(dengerin|coba bayangin|lo harus|serius nih|ini penting|perhatiin|liat nih|bro|guys|eh|oi)\b/i
  /[!]{1,}/ (single exclamation also counts — not just clusters)
  Direct address: /\b(lo|gue|kamu|bro|guys|sis)\b.*\b(harus|wajib|perlu|mesti)\b/i
```

#### `has_foreshadow` — Expand trigger patterns
```
ADD: /\b(ini dia|yang bikin|siapin diri|prepare|brace yourself|here it comes|here goes)\b/i
```

#### `has_value_delivery` — Expand action patterns
```
ADD: /\b(contoh|example|misalnya|kayak|seperti|like when|for instance|jadinya|hasilnya|result)\b/i
```

### 1.4 Word Density Curve Softening (12-scoring-engine.ts → `WORD_DENSITY`)

```
BEFORE:                              AFTER:
optimal: 70-90%                      optimal: 60-95%
60-70% → 0.7                         55-60% → 0.7
>90-100% → 0.8                       >95-105% → 0.7
>100-110% → 0.4                      >105-115% → 0.4
>110% → 0.1                          >115% → 0.1
<60% → 0.5                           <55% → 0.5
```

### 1.5 Weakness Threshold Adjustment (scriptAnalysis.ts → `analyzeSegment`)

```
BEFORE: points > 0 && points >= rule.weight * 0.5 → strength
AFTER:  points > 0 && points >= rule.weight * 0.4 → strength
```
This means features scoring 40%+ of max weight count as strengths (less issues shown).

## Part 2: LLM Prompt Enhancement

### 2.1 Stronger Enforcement in Scoring Cheat Sheet (generate-script/index.ts)

**Current problem:** Cheat sheet says "ALL 4 required" for HOOK but LLM still skips features.

**Enhancement:** Add penalty framing + mandatory feature count:

```
HOOK — MINIMUM 4 of 5 features REQUIRED (auto-reject if < 4):
1. ❓ Question with ? mark  [12pts — MANDATORY]
2. 🔢 Number/digit          [15pts — MANDATORY]
3. ⚡ POWER WORD in CAPS    [10pts — MANDATORY]
4. ❌ Negative frame word    [8pts — HIGH PRIORITY]
5. 🚫 Do NOT reveal payoff  [10pts — MANDATORY]

⚠️ HOOK with < 4 features = FAILED SCRIPT. Regenerate.
```

### 2.2 Concrete `builds_on_hook` Instruction

**Add to scoring cheat sheet:**
```
FORE — MUST reference at least 1 keyword from HOOK:
  If HOOK says "3 kesalahan branding" → FORE must contain "kesalahan" OR "branding"
  If HOOK says "5 AI tools" → FORE must contain "AI" OR "tools"
```

### 2.3 Emotion Intensity Boost for PEAK

**Add to scoring cheat sheet:**
```
PEAK — Emotional intensity MUST be highest segment:
  ✅ Use ALL CAPS for 1-2 key words: "ini LITERALLY game changer"
  ✅ Use superlative: "paling gila", "terbesar", "terbaik"
  ✅ Use at least 1 high-intensity word: GILA, PARAH, SHOCKING, INSANE, BRUTAL
  ✅ Add surprise/reveal: "ternyata", "plot twist", "actually"
```

### 2.4 Power Word Bank per Language (scoringOptimizer.ts)

**Add explicit top-10 power word list to the prompt:**
```
🇮🇩 ID Power Words (USE 2-3 per script minimum):
  GILA • PARAH • RAHASIA • FATAL • BAHAYA • KESALAHAN • GRATIS • WAJIB • BRUTAL • SHOCKING

🇺🇸 EN Power Words:
  INSANE • SECRET • FREE • SHOCKING • WORST • WARNING • HACK • TRUTH • EXPOSED • DEAD
```

### 2.5 Post-Generation Score Check in Self-Verification

**Add to verification checklist:**
```
SCORING SELF-CHECK (estimate before outputting):
□ HOOK: Has question? + number? + power word? + negative? = ≥4/5 features
□ FORE: Contains keyword from HOOK? + foreshadow trigger?
□ BODY: Each has pattern interrupt? + specific detail? + transition word?
□ PEAK: Has twist/reveal? + CAPS word? + proof/number? + highest emotion?
□ CTA: Has action verb? + first person? + urgency? + single focus?
□ If ANY segment has < 3 features → REWRITE that segment before output
```

## Risk Assessment

- **Scoring too lenient?** — No, because we're still requiring actual features. We're just widening detection (catching real patterns that were missed) and softening harsh defaults (0.2 → 0.4 for "normal" content).
- **LLM over-optimizing?** — Possible but desirable. If LLM produces scripts that consistently hit 90%+, that means it's including questions, numbers, power words, pattern interrupts — all proven to boost real-world retention.
- **Breaking existing tests?** — Need to re-run `validate-scoring-engine.ts`. Expect some threshold adjustments needed.
